# 配音要求：给配音 agent / 配音方

这份要求的目的是让配音**好画**。画面要跟着声音一笔一笔画出来，所以声音里需要留出“手”的时间。
最终制作以实际交付的配音为准；下面是让成片更好的建议和必须满足的交付格式。

## 一、节奏建议

| 项目 | 建议 | 原因 |
|---|---|---|
| 平均语速 | 每秒 3.8–4.3 个字 | 每秒 4.7 字以上时，一句话的时间只够画几笔，画面会被迫“快进” |
| 句间停顿 | 0.5–0.8 秒 | 笔要抬起、移到下一个位置 |
| 段落之间（稿子里的空行） | 1.0–1.5 秒 | 换板面或擦板需要约 0.7 秒，必须落在停顿里 |
| 关键数字、专有名词前 | 轻顿 0.2–0.3 秒，并放慢读 | 数字要写出来，观众要看清 |
| 设问之后 | 停 0.6–1.0 秒 | 给小人一个“想一想”的反应时间 |
| 列举（A、B、C） | 每项之间停 0.3 秒左右 | 每一项要各画一个东西 |
| 反转、结论句之前 | 停 0.8 秒左右 | 留给圈重点、打叉这类动作 |

不要为了凑时长整体变速。需要快就改稿子，不要压缩停顿。

## 二、稿子怎么写更好画

- **一句话只讲一件事。** 一句里塞三个动作，画面只能选一个画。
- **先说东西，再说它怎么了。** “政府从公司收走一百块”比“一百块被收走了，是政府从公司那儿收的”好画。
- **数字说整、说具体。** “五十三块”比“一半多一点”好画。
- **段落 = 画面的一个场景。** 用空行分段，一段讲完整的一件事（10–30 秒）。
- 提交给 TTS 的文本保留标点；字幕断句依赖它。

## 三、必须交付的东西

1. **一条连续的音频**：`narration.wav`（建议 48 kHz、16-bit、单声道）。不要分段交付再拼接。
2. **逐字时间表**：`alignment.json`，相对于这条音频的开头，单位秒：

```json
{
  "duration_seconds": 221.05,
  "units": [
    { "text": "你", "display_text": "你", "start": 0.000, "end": 0.155,
      "confidence": 0.94, "timing_warnings": [], "sentence_index": 0 },
    { "text": "信", "display_text": "信，", "start": 0.705, "end": 1.145,
      "confidence": 0.96, "timing_warnings": [], "sentence_index": 0 }
  ],
  "sentences": [
    { "text": "你相不相信，…打钱？", "start": 0.0, "end": 4.575, "unit_range": [0, 25] }
  ]
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `units[].text` | 是 | 一个字（或不可再分的词，如 “AI”），不含标点 |
| `units[].start` / `end` | 是 | 秒 |
| `units[].display_text` | 建议 | 带上紧跟其后的标点，用于字幕断句 |
| `units[].confidence` | 建议 | 低于 0.6 会被视为“时间不可靠” |
| `units[].timing_warnings` | 建议 | 非空即视为“时间不可靠”。数字、英文缩写的时间常常不准，请如实标记 |
| `units[].sentence_index`、`sentences` | 建议 | 缺失时按句末标点自动分句 |
| `duration_seconds` | 建议 | 音频总时长 |

只有 SRT 也能做，但只有句级精度，句内卡点是估算的。

## 四、交付后不要做的事

- **不要对音频再做剪切、变速、去静音**。任何改动都会让时间表失效，必须重新对齐。
- 不要把时间表的时间基准换成别的（必须相对最终音频的开头）。
- 改稿重配后，请交付**完整的**新音频和新时间表。画面的卡点是按口播文字绑定的，稿子没改的部分会自动对上。
