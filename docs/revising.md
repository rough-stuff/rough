# 返工手册：把修改意见变成几行改动

返工是常态。这个框架的结构就是为了让修改落在**尽量少的几行**上：

- 一个场景一个文件，场景之间互不影响。
- `elements` 管位置和长相，`beats` 管时间和动作。
- 卡点是口播原文，位置大多是相对的。动一处，其余自动跟随。
- 画面是时间的纯函数：`hj stills --at` 可以直接看任意一刻，不用等渲染。

## 流程

1. 找到意见对应的场景文件（`hj check` 会列出每个场景的时间段）。
2. 只改相关的几行。
3. `hj check <项目>`。
4. `hj stills <项目> --scene <场景>` 看这个场景的联系表；或 `--at "口播片段"` / `--at 31.5` 看某一刻。
5. `hj render <项目> --scene <场景> --draft` 只渲染这一段确认动态效果。
6. 全部改完再 `hj render <项目>` 出全片。

## 意见 → 改哪儿

| 用户说 | 改什么 |
|---|---|
| “这个东西往左一点 / 大一点” | 那个元素的 `dx` / `dy` / `size` |
| “这两个挤在一起了” | 其中一个的 `gap` 或 `dx`/`dy`；靠相对定位挂在它身上的元素会自动跟着走 |
| “颜色太多 / 这个要红的” | 元素的 `color` / `fill` |
| “出来得太早 / 太晚” | 节拍的 `at` 换一个口播片段，或加 `lead` / 在锚点后写 `+0.2` |
| “画得太快，看不清” | 把这一拍拆成两拍；或把元素换成更简单的；或加 `lead` 提前起笔 |
| “这里停太久没东西看” | 在那段口播上加一拍：换姿势、圈重点、推镜头 |
| “这句话没表现出来” | 在对应场景加元素和节拍。读 directing.md 第三节找手法 |
| “字太多了” | 删掉文字元素，换成图标/小人动作；或缩成关键词 |
| “这个图看不懂” | 加 `label`；或换一个更常见的图标（`hj assets icons`） |
| “小人没反应，太木” | 在关键句上加 `pose` / `face` 动作 |
| “这段不要了 / 两段合并” | 删掉场景文件，或把一个文件的 `elements`、`beats` 并入另一个（注意 id 不要重名）。属于分镜变更，需要重新确认 |
| “顺序换一下” | 口播顺序决定画面顺序。先改稿子重新配音，再改分镜 |
| “换成横屏” | `project.yaml` 的 `format`，然后逐场景重摆 `elements` 的位置；`beats` 基本不用动 |
| “字幕有错字 / 断句不好” | 字幕来自时间表。改 `voice/alignment.json` 里对应字的 `display_text`；断句调 `subtitleMaxChars` |
| “音效太吵” | `project.yaml` 的 `sfxVolume`，或 `sfx: false` |

## 换了配音怎么办

把新的 `alignment.json`（和音频）覆盖进 `voice/`，跑 `hj check`。

- 稿子没变：所有卡点自动对上新时间，通常只需要处理新出现的“太赶”或“静止太久”警告。
- 稿子改了几个字：`hj check` 会准确报出哪些锚点找不到了，逐个改成新稿里的文字即可。

## 什么改动需要用户重新确认

`hj check` 最后一行会显示确认状态。

- **不需要**：位置、大小、颜色、时长、`lead`、动作的增减与细节、元素的增减。
- **需要**：增删场景、改 `from`、改 `enter`、改场景或节拍的 `intent`、增删节拍、改节拍的 `at`。

原则是：用户确认的是“每句话画什么”。这个没变，就不用再问；变了，就得再问。
即便不需要重新确认，改完也要如实告诉用户你动了什么。
